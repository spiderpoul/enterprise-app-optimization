# Инварианты фронтенда

Владелец: @platform-frontend · Проверено: 2026-09 · Проверки: `npm run check:architecture`, `npm run check:bundle`, `npm run check:memory`

Инварианты описывают, какой должен получиться результат. Какой React API или какую оптимизацию для этого взять, они специально не диктуют.

## Стабильность компонентов

Компонент не перемонтируется, если это не задумано. Не объявляй компоненты внутри рендера другого компонента: посторонний ререндер не должен сбрасывать локальный стейт, эффекты и DOM.

## Стоимость рендера

Тяжёлая синхронная работа не должна повторяться на посторонних ререндерах. Производные данные пересчитываются только для того, что изменилось. Прежде чем что-то оптимизировать, подтверди проблему профайлером или минимальным репро.

## Владение и жизненный цикл

Кто захватил ресурс, тот его и освобождает. Таймеры, подписки, observer'ы, запросы, event listener'ы и ссылки на DOM останавливаются или освобождаются в cleanup, когда владелец размонтируется. Долгоживущий стейт приложения не держит detached DOM-узлы.

## Роуты и lazy-загрузка

Каждая страница продукта — отдельный lazy-чанк. Код страницы грузится, только когда пользователь открыл её роут; регистрация роута или пункта меню не должна тащить код фичи в стартовый бандл shell. В микрофронте одного `import()` для этого мало — см. «Подводные камни» и «Lazy-чанки через shell» в [microfrontends.md](./microfrontends.md).

## Границы зависимостей

Shell отвечает за общие задачи приложения и общий браузерный рантайм. Микрофронт отвечает за свой UI и работу со своим API, не импортируют друг друга и общаются с shell только через manifest, модуль роута и описанные серверные контракты. Контракт рантайма — в [microfrontends.md](./microfrontends.md).

## История этих правил

PR по производительности React с #24 по #54 вскрыли компоненты, объявленные внутри рендера, лишние перемонтирования и повторяющуюся синхронную работу. Цепочка по памяти PR #28 → #36/#38 → #55 прошла путь от «кажется, течёт detached DOM» до воспроизводимой проверки в MemLab. Эти истории объясняют, откуда взялись инварианты; конкретные решения из них не стоит считать общими правилами.
