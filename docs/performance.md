# Производительность фронтенда
Владелец: @perf-guild · Проверено: 2026-09 · Проверки: npm run check:bundle, npm run check:memory

## Как сейчас правильно
1. Страницу продукта подключай через lazy-роут: React.lazy + Suspense в элементе роута.
2. Ресурс освобождает тот, кто его захватил: observer, таймер, подписка — в cleanup эффекта.
3. Компоненты объявляй на уровне модуля, тяжёлые вычисления пересчитывай при смене данных, а не на каждый рендер.
Таблицу с пагинацией проверяй сценарием MemLab на базе tests/memlab/create-route-pagination-scenario.js.

## Подводные камни
- Утечку не видно ни в сборке, ни в тестах: страница работает, а после 40 страниц
  пагинации память только растёт. Ловит только npm run check:memory для этого роута.
- Тяжёлый расчёт в рендере не выглядит ошибкой: код короткий и понятный. А в фильтре
  визарда каждое нажатие клавиши блокирует UI на ~150 мс. Видно только в React Profiler.
- `import()` в продукте без своего Babel-конфига не создаёт чанк, а чанк с publicPath «/»
  через shell не загрузится — см. «Lazy-чанки через shell» в docs/architecture/microfrontends.md.

## Старт

Зависимости между шагами инициализации описаны явно. Независимые блокирующие шаги не ждут друг друга без причины, а неблокирующая инициализация не задерживает интерактивный UI. Важен правильный граф зависимостей, а какой Promise-комбинатор для этого взять — дело второе.

Проверка: если меняется поведение старта, разбери граф зависимостей инициализации и замерь, когда UI становится интерактивным. `check:startup` нет специально: пока этот замер не получается сделать стабильным.

## Бандл и загрузка

Каждый роут продукта грузится своим lazy-чанком. Код фичи не попадает в стартовый бандл shell, нужные lazy-чанки собираются, стартовые ассеты укладываются в допуск baseline. Общие runtime-зависимости не дублируются в бандле микрофронта.

Проверка: `npm run check:bundle`. Для расследования — `npm run analyze`.

В микрофронте один `import()` чанк не создаёт (корневой Babel-конфиг превращает его в `require()`), а чанк ещё должен быть доступен через shell. Прежде чем чинить «lazy-чанк не собран», прочитай «Подводные камни» и «Lazy-чанки через shell» в `docs/architecture/microfrontends.md`.

## Рендер React

Компонент не перемонтируется, если это не задумано. Тяжёлая синхронная работа не повторяется на посторонних ререндерах. Замеряй конкретное действие и вычисление; мемоизация и debounce — варианты решения, а не обязательные правила.

Проверка: lint и сборка, а для изменений, которые влияют на рендер, — запись React Profiler или performance-трейс в браузере.

## Память и жизненный цикл DOM

После навигации долгоживущие структуры приложения не держат detached DOM-узлы. Ресурсы и observer'ы освобождаются в cleanup, когда компонент размонтируется.

Проверка: подними приложение в режиме, близком к prod, на `MEMLAB_APP_BASE_URL` и явно передай сценарий роута, который менял, например `npm run check:memory -- tests/memlab/device-security.scenario.js`. Сценарий собирается на базе `tests/memlab/create-route-pagination-scenario.js`: выполняет действие, проверяет, что страница пагинации правда сменилась, и уходит со страницы, чтобы MemLab сравнил снапшоты. Сценарий другого роута про твой роут ничего не доказывает.
