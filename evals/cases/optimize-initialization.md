# Ускорить инициализацию
Стартовый коммит: 186f075

## Задача            ← агенту отдаём только это
Сократи время до интерактивного UI, сохранив обязательные
зависимости инициализации и поведение при ошибках.

## Критерии          ← агент их не видит
- зависимости между шагами инициализации описаны явно
- независимые блокирующие шаги не ждут друг друга без причины
- неблокирующая работа не задерживает интерактивный UI
- ошибки не проглатываются; понятно, кто владеет ресурсами и кто их освобождает
- замер времени до интерактивного UI до и после, а не только зелёная сборка

## Проверка
grader пока нет: оцениваем руками; детерминированного `check:startup` нет

## Откуда кейс
PR #49 запустил bootstrap и permissions параллельно, а остальное увёл в фон;
его смёржили и откатили в #61. Открытый PR #64 предлагает это снова.

## Классы ошибок (скрыты, для разбора упавших прогонов)
- Зависимые шаги запустили параллельно, не глядя на зависимости.
- Фоновую работу всё равно ждут на критическом пути.
- Изменилась семантика ошибок или появился необработанный reject.
- Зелёную сборку выдали за доказательство, что старт ускорился.
