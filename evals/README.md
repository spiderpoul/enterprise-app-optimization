# Evals: автотесты для агента

## Что такое eval
Автотест для агента. Одна задача, фиксированный стартовый коммит, скрипт-проверка (grader),
N попыток → доля успехов. Обычный тест спрашивает «работает ли код?». Eval спрашивает «справляется
ли агент с задачей в этом репозитории — и как часто?».

## Зачем
Мы меняем то, что читает агент: AGENTS.md, `docs/architecture/`, скиллы и субагентов в `.agents/`,
или обновляем модель. После такого изменения всегда кажется, что стало лучше. Eval отвечает, стало
ли на самом деле: тот же кейс до и после, та же проверка, несколько попыток.

## Как устроен кейс
`cases/<name>.md`:
- **Стартовый коммит** — откуда начинается каждая попытка.
- **Задача** — единственное, что видит агент.
- **Критерии** — что считаем успехом; агент их не видит.
- **Проверка** — grader в `graders/<name>.cjs`: команды с кодами выхода, печатает одну строку JSON.
- **Откуда кейс** — реальный промах, из которого он вырос.
- **Классы ошибок** — скрытая подсказка для разбора упавших попыток.

Пока grader есть только у `add-microfrontend`: архитектурная проверка, бандл, lint, продукт
`audit-log` с роутом `/audit-log`, нет Module Federation, нет правок в `common/`, в отчёте агента
упомянут `check:architecture`. Остальные кейсы оцениваем руками по критериям, пока реальные промахи
не подскажут, каким должен быть их grader.

## Как запустить
```bash
EVAL_AGENT_CMD='<CLI вашего агента в неинтерактивном режиме>' evals/run-case.sh add-microfrontend 5
```
Для каждой попытки скрипт создаёт чистый git worktree на стартовом коммите (или на `EVAL_REF`),
удаляет из него `evals/`, чтобы агент не прочитал критерии, ставит зависимости (`EVAL_SETUP_CMD`,
по умолчанию `npm ci`), отдаёт агенту текст задачи, сохраняет его отчёт, запускает grader и дописывает
результат в `results/<дата>-<кейс>.jsonl`. Последняя строка вывода — `прошло 3 из 5`.

До и после изменения harness:
```bash
EVAL_REF=origin/main evals/run-case.sh add-microfrontend 5   # «До»
EVAL_REF=HEAD        evals/run-case.sh add-microfrontend 5   # «После»
```
Оценить готовый worktree руками:
`node evals/graders/add-microfrontend.cjs --worktree <dir> --base <commit> --report <file>`
(`--dry-run` покажет, что будет запущено, `--help` — все параметры).

## Как читать результат
- **pass@k** — «хотя бы одна из k попыток прошла». Годится, когда человек выберет лучший вариант
  из нескольких.
- **pass^k** — «прошли все k попыток». Годится, когда агент работает сам и каждый промах кому-то
  разгребать: в CI, в ночных задачах.
- 3 из 5 — это pass@5 = да, pass^5 = нет. Для harness нам важнее, чтобы доля успехов росла
  и не падали соседние кейсы.
- Пять попыток — не статистика, но они отличают «помогло» от «один раз повезло».

## Когда запускать
- MR в AGENTS.md, `docs/` или `.agents/` — быстрый набор: кейсы, которые изменение может задеть.
  Цифры — в таблицу «Изменение harness» шаблона PR.
- Ночью — весь набор: видно, какие кейсы просели.
- Обновление модели или агентного CLI — весь набор на старой и на новой версии.

## Откуда брать кейсы
Из реальных промахов: агент ошибся в настоящем MR, ревьюер пометил замечание CI как «пропустил»,
команда объясняет агенту одно и то же каждую неделю. Выдуманные кейсы проверяют то, что и так
работает. Anthropic советует начинать с 20–50 задач из реальных провалов:
https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

## Частые ошибки
- **Ответ в задаче.** Если в тексте задачи подсказка из критериев, кейс проверяет чтение, а не работу.
- **Одна попытка.** Один прогон до и один после ничего не доказывает — агент недетерминирован.
- **Оценка слов агента вместо состояния репозитория.** «Я всё проверил» — не результат; результат —
  код выхода проверок, diff и файлы.
- **Синтетические кейсы.** Придуманная задача без реального промаха улучшает то, что и так работает.
- **Разные условия.** Между «до» и «после» меняется только harness: та же модель, настройки, задача,
  стартовый коммит и окружение (запиши их в `EVAL_LABEL`).
- **Проверка, которую агент может поправить.** Grader запускает свои копии `scripts/check-*.cjs`
  и `performance/bundle-baseline.json`, поэтому результат не зависит от файлов, которые правил агент,
  и оценивается даже стартовый коммит без этих скриптов.

## Файлы
- `cases/*.md` — кейсы; `graders/*.cjs` — проверки; `run-case.sh` — запуск;
  `results/` — локальные результаты, в git не попадают.
