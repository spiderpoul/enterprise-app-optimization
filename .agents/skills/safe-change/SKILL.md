---
name: safe-change
description: 'Используй перед изменением общего кода или публичных контрактов — всего, что есть
  в таблице «Что ещё заденешь» в AGENTS.md: common/, shell-app/server/, manifest, загрузка
  продуктов в shell, общие зависимости. Для правок внутри одного продукта не нужен.'
---

1. Назови контракт, который задеваешь. Начни с таблицы «Что ещё заденешь» в AGENTS.md и раздела
   «Blast radius» нужной документации.
2. Найди реальных потребителей поиском (импорты, id из manifest, пути роутов). Если задето больше
   одного продукта, поручи поиск субагенту `explorer`. Потребителей перечисли как file:line.
3. Выбирай аддитивный порядок: добавить новое → перевести потребителей → удалить старое отдельным
   изменением. Никогда не переименовывай id или роут в manifest на месте.
4. Напиши отчёт о влиянии ДО правки. Остановись и спроси владельца из CODEOWNERS, если потребитель
   может жить вне репозитория или придётся ослабить baseline.
5. Внеси изменение. Запусти проверки для каждой задетой области, а не только для правленого файла.
6. Отчёт: таблица влияния, проверки с результатами, шаг отката.

| Что меняется | Потребители (file:line) | Риск | Проверка | Откат |
|--------------|-------------------------|------|----------|-------|

## Пример отчёта о влиянии
Запрос: «переименуй роут Users & roles из `/users` в `/users-and-roles`».

| Что меняется | Потребители (file:line) | Риск | Проверка | Откат |
|--------------|-------------------------|------|----------|-------|
| `routePath` в manifest | `src/microfrontends/users-and-roles/manifest.json:5` | fallback-роут переедет | `npm run check:architecture` | вернуть значение |
| экспортированный `path` роута | `src/microfrontends/users-and-roles/client/index.tsx:9`; ссылка меню строится из него в `src/shell-app/client/components/MainLayout.tsx:305` | меню переедет вместе с ним | smoke: открыть из меню | вернуть значение |
| ссылки внутри продукта | `src/microfrontends/users-and-roles/client/routes/UsersList.tsx:107`, `…/routes/UserDetails.tsx:37` — относительные пути | нет | smoke: открыть пользователя, вернуться | — |
| сохранённые ссылки, закладки, документация | вне репозитория | `/users/...` покажет Not Found | здесь не проверить | — |

Итог: остановиться и спросить @platform-frontend. Потребители живут вне репозитория, для аддитивного
порядка старый путь должен продолжать работать, а shell регистрирует один роут на продукт
(`src/shell-app/client/microfrontends/useMicrofrontends.ts`). Для редиректа сначала придётся менять shell.
