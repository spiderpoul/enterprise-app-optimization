# Реестр скиллов

Скилл — это процедура: шаги, стоп-условия, результат. Знания живут в `docs/`, короткие правила
«всегда / никогда» — в `AGENTS.md`, правила, которые проверяет машина, — в `scripts/`. Пока агент
не открыл скилл, он видит только `description` из frontmatter SKILL.md, поэтому description говорит,
когда скилл брать и когда не брать.

| Скилл | Что делает | Когда брать | Владелец | Eval-кейс |
|---|---|---|---|---|
| [story-analysis](story-analysis/SKILL.md) | Разбирает тикет до кода: вопросы, затронутые контракты, черновик спеки в `openspec/changes/` | Задача пришла текстом из трекера, спеки ещё нет | @platform-frontend | пока нет (пробный) |
| [safe-change](safe-change/SKILL.md) | Отчёт о влиянии до правки, аддитивный порядок, шаг отката | Меняешь общий код или публичные контракты: `common/`, `shell-app/server/`, manifest, загрузку в shell, общие зависимости | @platform-frontend | `add-microfrontend` (проверка `inScope`: нет правок в `common/`) |
| [performance-check](performance-check/SKILL.md) | Определяет класс изменения и выбирает проверки бандла, памяти, рендера или старта | После изменения, которое может задеть загрузку, рендер, память или старт | @perf-guild | `add-lazy-route`, `add-large-table`, `fix-memory-leak`, `optimize-initialization` |
| [log-trace-analysis](log-trace-analysis/SKILL.md) | Скрипт группирует ошибки по трейсам, модель объясняет первую ошибку и называет код | Логи, HAR или трейсы длиннее 300 строк | @observability | пока нет (пробный); скрипт проверяется на `log-trace-analysis/fixtures/sample.log` |
| [ui-form](ui-form/SKILL.md) | Собирает или меняет форму на UI-ките: поля, валидация, состояния, доступность, test id | Создаёшь или меняешь форму продукта | @design-system | пока нет (пробный) |
| [security-check](security-check/SKILL.md) | Ищет входы извне и куда они уходят: авторизация эндпоинтов, allowlist прокси, CORS, XSS, секреты, `npm audit` | Изменения серверного кода, прокси, регистрации продуктов, заголовков, токенов и пользовательского ввода | @security-champions | пока нет (пробный); первый кейс — «эндпоинт без авторизации» |
| [code-review](code-review/SKILL.md) | Ревью diff по контрактам репозитория; каждое замечание ссылается на правило | Локально перед MR и в CI через `.github/workflows/agent-review.yml` | @platform-frontend | пока нет (пробный); каждое замечание CI с пометкой «пропустил» или «шум» становится кейсом |

## Как добавить или изменить скилл
1. Начни с реального промаха: задачи, которую агенты раз за разом делают не так или которую ты
   объясняешь им каждую неделю.
2. Добавь для неё eval-кейс в `evals/cases/` и приложи к MR прогоны до и после (`evals/run-case.sh`);
   таблица — в разделе «Изменение harness» шаблона PR.
3. Держи SKILL.md короче 100 строк. Детерминированная работа — в `scripts/`, длинные справочники —
   в `references/`, знания — в `docs/`.
4. MR одобряет владелец из `.github/CODEOWNERS`. Скилл без владельца — чей-то личный промпт.

Скиллы с пометкой «пробный» ещё без eval-кейса. Ими можно пользоваться, но следующее изменение
такого скилла приходит вместе с первым кейсом.
Личные эксперименты остаются локально; общий `.agents/` меняется только через MR.
