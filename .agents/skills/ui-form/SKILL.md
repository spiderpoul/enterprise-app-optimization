# Форма на нашем UI-ките

Эталонной формы продукта в репозитории пока нет: `Field` и `Textbox` в `src/` нигде не используются.
Ближе всего к форме — визард из воркшопа по React-производительности,
`src/shell-app/client/pages/workshop/react-perf/wizard/steps/SecurityQuickSetupStep.tsx` и
`PolicyTuningStep.tsx`. Это специально собранный набор антипаттернов: нативные `<select>`/`<input>`,
шаги перемонтируются на каждое изменение стейта, тяжёлые вычисления живут рядом со стейтом инпутов.
Смотри на него, только чтобы понять, как страница shell раскладывается на Hexa UI (`Space`, `Text`);
его контролы и работу со стейтом не копируй. Когда смёржат первую настоящую форму, впиши её сюда
как эталон.

## Шаги
1. Найди, где живёт форма, и бери кит, который уже используется в этой области:
   - страница shell (`src/shell-app/client/`) → Hexa UI, `@kaspersky/hexa-ui`;
   - продукт (`src/microfrontends/<name>/client/`) → собственный кит продукта (сейчас antd; см. «Остановись и спроси»).
2. По спеке выпиши каждое поле: имя, контрол, обязательность, правило валидации, значение по умолчанию,
   текст ошибки и как на него ложится ошибка сервера. Нет правила или текста — это вопрос, а не догадка.
3. Каждое поле собирай через обёртку поля из кита, а не голыми HTML-контролами:
   Hexa UI `Field` (`label`, `required`, `control`, `description`, `message`, `messageMode`) вокруг
   `Textbox` / `Select` / `Checkbox` / `Toggle` (`validationStatus` или `invalid`); несколько полей →
   `FieldSet` с `items`. В antd: `Form.Item` (`label`, `name`, `rules`) вокруг контролов antd.
4. Покрой каждое состояние из `references/form-checklist.md`: начальная загрузка, нетронутая форма,
   ошибка валидации, отправка, ошибка сервера, успех, disabled / только чтение.
5. Доступность: у каждого контрола видимая связанная подпись, ошибки — текстом (не только цветом),
   при отправке фокус уходит на первое невалидное поле, Enter отправляет, изменённая форма
   предупреждает перед уходом.
6. Test id: `testId` (Hexa UI) или `data-testid` на форме, каждом поле и кнопке отправки,
   по имени поля. Существующие id публичны (MemLab, e2e): никогда их не переименовывай.
7. Стейт полей держи внутри формы; никаких тяжёлых вычислений на каждое нажатие клавиши
   (`docs/architecture/frontend.md`, «Стоимость рендера»). При размонтировании отменяй незавершённую отправку.
8. Запусти `npm run lint`, сборку затронутого проекта (`npx nx run <project>:build`) и проверки
   из активной спеки. Пройди каждое состояние один раз в запущенном приложении.

## Остановись и спроси
- Форма живёт в микрофронте, и ей нужен Hexa UI: он резолвится из hoisted `node_modules`,
  но не является зависимостью продукта, а собранная внутрь копия не получит тему из `ConfigProvider`
  shell. То же для любой другой новой зависимости.
- Правила валидации, текста ошибки, значения по умолчанию или адреса отправки нет в спеке.
- Изменению нужен `src/microfrontends/common/` или другой продукт: используй скилл safe-change.
