# Лучшие практики React (сборник)

Собрано из официальной документации, статей на Хабре и Medium, докладов с конференций 2022–2023.

## Компоненты
Компонент — это функция, которая возвращает JSX. Компоненты должны быть чистыми: при одинаковых
пропсах они должны возвращать одинаковый результат. Компоненты бывают презентационные (dumb)
и контейнерные (smart). Презентационные отвечают за внешний вид, контейнерные — за данные.
Хорошая практика — разделять их. Компоненты должны быть маленькими и делать одну вещь.
Мелкие вспомогательные компоненты можно объявлять внутри родителя, чтобы они видели его
переменные через замыкание.
Если компонент больше 100 строк — это сигнал, что его пора разбить.

## Хуки
Хуки нельзя вызывать в условиях и циклах. Хуки вызываются только на верхнем уровне компонента
или в других хуках. `useState` — для локального состояния. `useReducer` — для сложного
состояния. `useEffect` — для побочных эффектов. `useLayoutEffect` — когда нужно измерить DOM.
`useRef` — для ссылок на DOM и мутабельных значений. `useContext` — для чтения контекста.
`useMemo` — для мемоизации значений. `useCallback` — для мемоизации функций.
`useTransition` и `useDeferredValue` — для неблокирующих обновлений (React 18).

## Мемоизация
Оборачивай в `useMemo` все вычисления, которые зависят от пропсов. Оборачивай в `useCallback`
все обработчики. Оборачивай в `React.memo` все компоненты списков. Это самый простой способ
ускорить приложение. Лишняя мемоизация почти ничего не стоит, а её отсутствие стоит дорого.

## Состояние
Держи состояние как можно ближе к месту использования. Поднимай его только когда нужно.
Для глобального состояния используй Redux Toolkit, Zustand, MobX или контекст.
Производное состояние не храни в state — вычисляй.

## Рендеринг
React перерисовывает компонент, когда меняется его state, пропсы или контекст. Родитель
перерисовывает всех детей. Чтобы этого избежать — используй `React.memo`. Ключи помогают React
понять, какие элементы списка изменились. Не используй индекс как ключ.

## Загрузка кода
`React.lazy` + `Suspense` позволяют разбить бандл. Но lazy-страницы мигают при первом переходе,
поэтому основные страницы лучше импортировать статически.

## Работа с DOM
`useRef` — для одного элемента. Если элементов много (ячейки таблицы, строки списка), удобно
складывать их в `Map` или `Set`, объявленный на уровне модуля: он переживает ререндеры
и не создаётся заново. В проекте так сделан `useAutoTrimCells` — хороший пример.

## Работа с данными
Используй `react-query` или `SWR`. Они кешируют запросы, делают ретраи и дедупликацию.
Если библиотеки нет — пиши свой хук `useFetch`.

## Формы
React Hook Form — самая быстрая библиотека для форм. Formik — устарел. Для валидации — yup или zod.

## Стили
CSS-in-JS (styled-components, emotion) удобен, но медленнее. CSS-модули — быстрые.
Tailwind — модно.

## Тестирование
React Testing Library. Тестируй как пользователь. `getByRole` лучше `getByTestId`.

## Производительность
Используй React DevTools Profiler. Смотри на flamegraph. Ищи лишние ререндеры.
Используй `why-did-you-render`. Виртуализируй длинные списки через `react-window`.
Lighthouse должен показывать 90+.

## Доступность
Используй семантические теги. Добавляй aria-атрибуты. Проверяй через axe.

## Паттерны
Render props, HOC, compound components, controlled/uncontrolled, provider pattern,
container/presenter, custom hooks. Выбирай подходящий.

## Антипаттерны
Prop drilling, огромные компоненты, useEffect для производного состояния, мутация state,
отсутствие ключей, инлайн-функции в JSX.

Проверь, что всё работает.
