# Проверка безопасности
Не пересказываем OWASP: ищем то, что в этом репозитории уже было или может быть опасно.

## 1. Найди входы извне
Что в diff приходит от клиента или другого сервиса: тело запроса, заголовки, URL, дескриптор
микрофронта. Для каждого входа запиши, куда он уходит: прокси, файл, ответ, HTML.

## 2. Проверь по списку
- новый или изменённый эндпоинт требует авторизации; регистрация и удаление продуктов — тоже
- цель прокси берётся из allowlist, а не из тела запроса (иначе shell — открытый прокси)
- нет `Access-Control-Allow-Origin: *` на ответах с данными пользователя
- ввод не попадает в HTML без экранирования (`dangerouslySetInnerHTML`, `innerHTML`)
- в клиентском бандле нет секретов и внутренних адресов
- `npm audit --omit=dev --audit-level=high` без новых находок

## 3. Когда остановиться
Нашёл blocker — не чини сам: опиши и остановись. Исправление согласует владелец
из CODEOWNERS, потому что оно почти всегда меняет контракт с другими командами.

## 4. Отчёт
Для каждой находки: severity (blocker | risk) · file:line · откуда вход и куда уходит ·
чем опасно · как исправить. В конце — что не проверено и почему.
