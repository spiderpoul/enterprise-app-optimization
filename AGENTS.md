## Лучшие практики React
- Используй функциональные компоненты и хуки.
- Используй useMemo и useCallback, где уместно.
- Классовые компоненты НЕ ИСПОЛЬЗУЙ. Никогда. Даже если очень хочется.
- Имена компонентов — в PascalCase, имена хуков начинаются с `use`.
- Не мутируй state напрямую, используй функциональный апдейт `setState(prev => ...)`.
- Ключи в списках (`key`) ОБЯЗАТЕЛЬНЫ. Индекс массива в качестве ключа — ПЛОХО.
- Используй `React.memo` для всех компонентов, которые получают пропсы.
- Не создавай функции внутри JSX — это вызывает лишние ререндеры!!!
- Маленькие вспомогательные компоненты (строка, ячейка, бейдж) объявляй прямо внутри родителя —
  так читаемее, всё в одном месте и не нужно прокидывать пропсы.
- Выноси бизнес-логику в кастомные хуки.
- Контекст используй только для глобальных вещей (тема, пользователь, локаль).
- Для форм используй контролируемые компоненты.
- Избегай prop drilling глубже 3 уровней.
- useEffect — это НЕ lifecycle. Думай о синхронизации, а не о «монтировании».
- Всегда возвращай функцию очистки из useEffect, если подписываешься на что-то.
- Не используй `dangerouslySetInnerHTML`. ВООБЩЕ.
- Хороший пример организации сложного UI — визард в `src/shell-app/client/pages/workshop/react-perf/`.
  Новые многошаговые экраны делай по его образцу.

## TypeScript
- `any` ЗАПРЕЩЁН. Используй `unknown` и сужение типов.
- Все пропсы описывай через `interface`, а не `type`.
- Экспортируй типы из `types.ts` рядом с компонентом.
- Используй `enum` для наборов констант.
- Включай `strict: true` (уже включено, не выключай).
- Не используй `!` (non-null assertion), кроме случаев, когда точно уверен.
- Дженерики называй осмысленно: `TItem`, а не `T`.
- Возвращаемый тип функций указывай явно.

## Стиль кода
- Отступ — 2 пробела. Точка с запятой — обязательно. Кавычки — одинарные.
- Максимальная длина строки — 120 символов.
- Импорты сортируй: сначала внешние библиотеки, потом внутренние, потом стили.
- Именованные экспорты лучше default-экспортов.
- Комментарии пиши на английском.
- Не оставляй `console.log` в коде!!!
- Магические числа выноси в константы.
- Функции не длиннее 50 строк. Файлы не длиннее 300 строк.

## ПРОИЗВОДИТЕЛЬНОСТЬ (ОЧЕНЬ ВАЖНО!!!)
IMPORTANT: производительность — наш главный приоритет в этом квартале.

- Держи бандл маленьким. Каждый килобайт на счету!
- Используй code splitting и `React.lazy` для тяжёлых компонентов.
- Не импортируй lodash целиком: `import debounce from 'lodash/debounce'`.
- moment.js — ТЯЖЁЛЫЙ. По возможности используй dayjs.
- Списки длиннее 100 элементов — виртуализируй.
- ВСЕГДА оборачивай вычисления в useMemo, а функции — в useCallback. Лишней мемоизации не бывает.
- Избегай анонимных объектов в пропсах: `style={{...}}` создаёт новый объект на каждый рендер.
- DOM-элементы, которые нужны часто (ячейки, строки), храни в `Map`/`Set` на уровне модуля —
  так быстрее, чем каждый раз искать их через `querySelector`.
- Дебаунсь инпуты поиска (300 мс).
- Не делай запросы в цикле.

## Архитектура
Проект — это Nx-монорепозиторий с микрофронтендами. Подробнее — в `docs/architecture.md`
и в Confluence: «Frontend Platform / Архитектура (актуально)».

- `src/shell-app` — оболочка.
- `src/microfrontends/*` — микрофронты.
- `src/microfrontends/common` — общее. НЕ ТРОГАЙ `common/` без согласования с платформенной командой!
- Новую страницу или микрофронт делай как у соседей: открой `DeviceSecurityPage` или
  `operations-reports` и сделай так же.
- Общие компоненты можно импортировать из соседнего микрофронта, если так быстрее. Главное — не копипастить.
- Роуты регистрируются в shell. Если непонятно где — поищи по проекту.
- API микрофронта проксируется через shell-server.

## Работа с данными
- Для запросов используй `fetch` или `axios` (что удобнее).
- Все запросы — через кастомный хук `useXxxData`.
- Обрабатывай ошибки!!! Всегда показывай пользователю понятное сообщение.
- Кешируй ответы, где возможно.
- Моки для разработки кладите в `server/data`.

## UI и стили
- UI-кит — antd. Свои кнопки и инпуты НЕ ПИШИ.
- Стили — CSS-модули или Tailwind, на твой выбор.
- Цвета — только из темы. Никаких `#fff` в коде!
- Адаптивность обязательна: проверяй на ширине 1280 и 1920.
- Таблицы — `Table` из antd, пагинация 50 строк.
- Для ячеек таблиц уже есть готовый хук `useAutoTrimCells` (`src/shell-app/client/shared/`) —
  используй его, не пиши свой.
- Импортируй страницы сразу (без lazy), чтобы не было мигания при загрузке.
- Анимации — не дольше 200 мс.

## Доступность (a11y)
- У всех картинок должен быть `alt`.
- У всех интерактивных элементов — доступное имя.
- Не используй `div` с `onClick` вместо кнопки.
- Контраст — не ниже AA.

## Тестирование
IMPORTANT: код без тестов не принимается!!!

- Юнит-тесты — Jest + React Testing Library.
- Тестируй поведение, а не реализацию.

- E2E — Playwright, сценарии лежат в `e2e/`.
