# Демо: прогон агента и отчёт

Два отдельных клона репозитория, в каждом свой агент: Run A — ветка `demo-before`, Run B —
`demo/agent-ready-v2`. Модель, настройки и версия агентного CLI одинаковые. Всё ниже делается в каждом
клоне одинаково: скрипт метрик (`docs/demo/`) и пакеты Chrome DevTools MCP лежат в main и есть в обеих
ветках. Ничего не переключаем, третий checkout не нужен.

## 1. Чистый клон — перед каждым прогоном

Прошлый прогон сначала сохрани (шаг 5), эти команды удаляют всё незакоммиченное.

```bash
git fetch origin
git checkout -B demo-before origin/demo-before   # во втором клоне: demo/agent-ready-v2 origin/demo/agent-ready-v2
git reset --hard && git clean -fd                # чтобы в отчёте не было чужих «M» и старого продукта
npm ci                                           # после этого есть node_modules/chrome-devtools-mcp

# Спрятать от агента то, что подсказывает решение: критерии evals, слайды и эту инструкцию.
git ls-files -z evals presentation docs/demo | xargs -0 git update-index --skip-worktree
rm -rf evals presentation docs/demo
git status --short                               # должно быть пусто
```

- Run B: `opencode mcp list` показывает `chrome-devtools` подключённым. В Run A MCP агенту не подключён.
- Оба клона используют порты 4300–4405: если агенты поднимают приложение, прогоняй их по очереди.

## 2. Промпт 1 — задача, одинаковый для обоих

```
Implement openspec/changes/add-application-security/. When you are done, write a short report in Russian to `agent-report.md` in the repository root: what you did, which checks you ran and their results, and your reasoning — key decisions, alternatives you rejected, doubts.
```

По ходу никаких подсказок. Если агент спрашивает — ответ один для обоих: «Do not change shared code;
this product's own files are yours. Finish what you can and report what is left.»

## 3. Промпт 2 — отчёт и замер, в той же сессии, сразу как агент закончил

```
Перепиши `agent-report.md` в корне репозитория: коротко, не больше 50 строк, только факты этой сессии, без пересказа кода и без оценок. Структура:

## 1. Решения и откуда взял правило
Таблица, 6–10 строк, по одной на каждое решение из списка: сборка клиента (Babel, modules), как подключена страница (статически, lazy, import()), require() или import для библиотек, мемоизация и React.memo, вспомогательные компоненты внутри страницы, хук для ячеек таблицы, .env и порты, сервер и CORS, что скопировал у соседнего продукта. Колонки: решение · где в моём коде (file:line) · откуда правило — файл и раздел, цитата в одну строку · или «правила не нашёл, скопировал с <файл>».

## 2. Что прочитал первым
3–5 файлов в порядке чтения до первой правки; какой продукт взял за образец.

## 3. Скиллы и субагенты
Что открывал и использовал. Если ничего — «не использовал».

## 4. Проверки
По строке: команда → результат (код выхода, ключевая фраза). Отдельно: что не запускал и почему. Поднимал ли приложение и открывал ли страницу в браузере.

## 5. На чём основано «готово»
Одно предложение.

## 6. Что сомнительно
1–3 пункта, где сам не уверен.

Когда отчёт записан, сделай замер. Это не проверка твоей работы: по его результату ничего не чини, ничего не переписывай и ничего не комментируй.
1. Если приложение запущено (npm run dev или другое) — останови его: порты 4300–4405 должны быть свободны.
2. Выполни `node docs/demo/measure-run.cjs --append-report`. Команда долгая, 10–15 минут: она сама собирает проект, поднимает его и открывает страницу в браузере. Если инструмент командной строки ограничивает время выполнения, запусти её в фоне с выводом в файл и дождись завершения.
3. Скрипт сам допишет в конец `agent-report.md` раздел «7. Метрики». Не правь его.
Если команда не запустилась или упала — одной строкой допиши в раздел «6. Что сомнительно», что именно произошло, и остановись.

Больше ничего не меняй: ни код, ни конфиги, ни другие файлы.
```

Если агент спрашивает — ответ один для обоих: «Пиши то, что было. Если не помнишь — так и напиши».

## 4. Метрики руками — только если агент не смог их снять

Останови приложение и в корне репозитория выполни `node docs/demo/measure-run.cjs --append-report`.
Скрипт сам понимает по ветке, Run A это или Run B, и код агента не меняет. Он собирает проект, поднимает
его как в production и через Chrome DevTools MCP меряет `/application-security` (LCP, CLS, JS до LCP),
проверяет, что пункт меню и таблица отрисовались и чем shell отвечает на entry и lazy-чанк. Потом поднимает
`npm run dev` и проверяет, открывается ли продукт там (ловушка «Failed to fetch dynamically imported module»).
Ещё считает `require()`, Babel, размер entry, `.env` и конфликты портов, правки вне продукта.
Результат — раздел «7. Метрики» в конце `agent-report.md` и полный `agent-metrics.md` с блоком «Коротко» сверху.

- Сравнить с соседними страницами: `--compare /users`. Быстрее, без `npm run dev`: `--no-dev`. Всё — `--help`.
- В контейнере под root: `WEB_VITALS_MCP_ARGS="--executablePath <chrome> --chromeArg=--no-sandbox"`.
- Нужен выполненный `npm ci`. Если в «Правки вне продукта» десятки файлов, которых агент не трогал, —
  клон был не чистый (шаг 1).

## 5. Сохранить результат

```bash
git checkout -b demo-results/run-a     # во втором клоне: demo-results/run-b
git add -A && git commit -m "Run A: код агента, отчёт и метрики"
git push -u origin demo-results/run-a
```

На докладе открываем `agent-report.md` обеих веток `demo-results/*` рядом: решения и цитаты — раздел 1, цифры — раздел 7.
