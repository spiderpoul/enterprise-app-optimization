# Сценарий live-показов

Для спикера. Номера слайдов — по текущему `slides.md` (основной поток — слайды 1–28, дальше запасные).
Этот файл заменяет разделы «Старт», «Live-чекин» и «Результаты» из `docs/demo/practical-demo-guide.md`
в ветке `demo/agent-ready-v2`: там описаны разные промпты для Run A и Run B, а доклад теперь исходит из одинакового.

## Условия сравнения

| | Run A | Run B |
|---|---|---|
| Ветка | `demo-before` | `demo/agent-ready-v2` |
| Модель, настройки, версия CLI | одинаковые | одинаковые |
| Промпт | одинаковый (ниже) | одинаковый (ниже) |
| Критерии оценки | пять вопросов со слайда 22 | те же |
| Что лежит в репозитории | общий AGENTS.md, `docs/architecture.md` 2021 года, `npm run check`, `check:ai` | AGENTS.md с картой и ограничениями, актуальные docs, спека к задаче, скиллы, субагенты, проверки |

Что сравнение показывает: как одна модель действует в двух по-разному подготовленных репозиториях.
Чего не показывает: вклад отдельного файла (меняется сразу многое) и повторяемость (один прогон на условие).
Так и говорим со сцены (слайды 8 и 23).

## Подготовка

1. Два чистых worktree только для агентов; файлы в IDE показываем из третьего checkout `demo/agent-ready-v2`:
   ```bash
   git fetch origin
   git worktree add --detach ../run-a origin/demo-before
   git worktree add --detach ../run-b origin/demo/agent-ready-v2
   (cd ../run-a && npm ci) && (cd ../run-b && npm ci)
   ```
2. Спрятать от агентов то, что подсказывает решение или превращает Run A в карикатуру:
   ```bash
   hide() { git -C "$1" ls-files -z -- "${@:2}" | xargs -0 git -C "$1" update-index --skip-worktree -- && (cd "$1" && rm -rf "${@:2}"); }
   # Run B: скрытые критерии eval, гайд с ловушками, слайды
   hide ../run-b evals docs/demo presentation
   # Run A: то же + спека с «заодно ускорить shell», зоопарк скиллов, «команда агентов»,
   # второй файл правил и ревью-бот
   hide ../run-a evals docs/demo presentation openspec .agents docs/ai .ai-review .github/workflows/ai-review.yml
   ```
   В Run A остаются AGENTS.md, `docs/architecture.md`, `npm run check` и `check:ai`: это «репозиторий, какой бывает»,
   и так он описан на слайде 8. AGENTS.md в `demo-before` ссылается на `docs/ai/rules.md` — пусть ссылка ведёт в никуда,
   мёртвые ссылки там и так есть.
3. Убрать из кода комментарии, которые прямо называют утечку (они есть в обеих ветках):
   ```bash
   for w in ../run-a ../run-b; do
     f=src/shell-app/client/pages/DeviceSecurityPage.tsx
     git -C "$w" update-index --skip-worktree -- "$f"
     sed -i -e 's| // 😈 утечка: хук навсегда держит DOM-ячейки в Map||' \
            -e 's| // 40 страниц по 50 строк — достаточно для демонстрации утечки||' "$w/$f"
   done
   ```
   Без этого слайд 9 («с самой страницы утечку не видно») не соответствует коду.
4. Проверить: `git -C ../run-a status --short` и `git -C ../run-b status --short` пустые;
   `grep -rn "😈\|демонстрации утечки" ../run-a/src ../run-b/src` ничего не находит;
   `ls ../run-a/openspec ../run-a/.agents ../run-b/evals` — «No such file or directory».
5. Одна модель, одинаковые настройки и версия CLI в обоих терминалах. Кэши сборки (`.nx/`, `node_modules/.cache`)
   прогреть или очистить одинаково. Порты 4300–4403 агенты делить не могут: приложение одновременно поднимет только один.
6. Открытые PR по производительности (#52–#55, #64) не мёржить: это история, в которой может копаться Run A.
7. Прогнать весь сценарий на репетиции и сохранить запасные артефакты (ниже).

## Промпт — одинаковый для обоих

> Add an Application Security page to the product: a menu item "Application Security" opens a paginated table of applications. When you are done, write a short report in Russian to `agent-report.md` in the repository root: what you did, which checks you ran and their results, and your reasoning — key decisions, alternatives you rejected, doubts.

Больше никаких подсказок. Если агент задаёт вопрос, записать его (это результат) и ответить обоим одной фразой:
«Do not change shared code; this product's own files are yours. Finish what you can and report what is left.»

### Чекин 1 (слайд 10): на что смотреть
- Run A: сколько файлов открыл до первой правки, какую таблицу взял за образец, забрал ли `useAutoTrimCells`,
  ссылается ли на `docs/architecture.md`.
- Run B: прочитал ли AGENTS.md → спеку → `docs/architecture/microfrontends.md` → `docs/performance.md` до кода;
  какой пример взял; позвал ли `explorer` (если да — можно открыть запасной слайд про explorer).

### Чекин 2 (слайд 18): на что смотреть
- Вероятное первое падение Run B — `npm run check:bundle`: «lazy-чанк не собран» (корневой Babel превращает `import()`
  в `require()`), затем сообщение про `publicPath` со слайда 17.
- Хороший исход — чинит в своём продукте по рецепту «Lazy-чанки через shell». Плохой — правит `common/`, shell,
  `scripts/` или `performance/`.
- Если Run B остановился и спросил про общий код — обязательно показать: это то, чего мы добиваемся.

### Результаты (слайд 22): где брать доказательства

| Вопрос | Как, в каждом worktree |
|---|---|
| Страница открывается через shell отдельным чанком? | `ls src/microfrontends/*/client/dist`; `npm run check:bundle` в Run B; открыть `/application-security` из меню |
| Память не растёт? | `MEMLAB_APP_BASE_URL=<url> npm run check:memory -- tests/memlab/application-security.scenario.js` при запущенном приложении |
| Нет лишних рендеров? | React Profiler: открыть таблицу, записать, свернуть и развернуть меню |
| Не трогал чужой код? | `git status --short`; `git diff --stat` |
| На чём основано «готово»? | `agent-report.md` обоих прогонов рядом |

В Run A нет `check:bundle` и `check:memory`, а приложение поднимается только для одного прогона.
Первые три строки для Run A снимаем на репетиции и так и говорим. Вживую для обоих — diff, список файлов и отчёт.

После доклада оба прогона можно оценить одной меркой: grader из `demo/agent-ready-v2`,
`node evals/graders/add-microfrontend.cjs --worktree ../run-a --base <стартовый коммит> --report ../run-a/agent-report.md --skip product`
и то же для `../run-b`. `--skip product` нужен, потому что кейс grader — про `audit-log`.

## Запасные артефакты

Хранить вне обоих worktree, с репетиции:
- начало транскрипта каждого прогона: что прочитал и какой образец выбрал (чекин 1);
- упавшая проверка Run B с сообщением и зелёный вывод после исправления (чекин 2);
- `git diff --stat` и полный diff каждого прогона;
- `agent-report.md` каждого прогона;
- снимки MemLab и React Profiler для первых трёх строк слайда 22;
- вывод `evals/run-case.sh add-microfrontend 5` и модель, на которой он получен (слайд 26).
